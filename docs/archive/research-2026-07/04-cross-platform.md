# 04 — Cross-platform: one codebase, four platforms

Condensed English summary of a 2026-07-25 research pass, baseline 26.0, 27-only noted separately.
Unlike the other reports, availability claims here were checked against the **installed Xcode 27
compiler** (`swiftc -typecheck -sdk … -target arm64-apple-tvos26.0` etc.), not just documentation —
marked "(compiler-verified)" below where that distinction mattered. Current guidance lives in
[`.claude/skills/tvos-surface/SKILL.md`](../../../.claude/skills/apple-chrome/SKILL.md). The
baseline-26 migration this report scoped **landed**: packages are on `.v26` /
`swift-tools-version: 6.2`, `SWIFT_VERSION` stays `5.0` with `swiftLanguageModes: [.v5]` (Swift 6
language mode deliberately deferred — see below), and the `legacyTabs` availability branch is gone.
Russian original: `04-cross-platform.ru.md` (gitignored, local only).

## TL;DR (at the time)

- The app had 158 `#if os(...)` directives (+10 `#if canImport`). Raising the deployment target
  alone would remove only ~8 of them (things that were already unnecessary pre-26); the realistic
  ceiling from replacing `#if os` with environment reads was ~25–30, i.e. 15–20%. The rest split
  into two permanent buckets: API genuinely absent on a platform, and 10-foot vs. pointer design —
  which should live in separate files, not scattered `#if` blocks.
- **`@available`, not `#if os`, is what baseline 26 actually paid off.** 14 availability points
  across 3 files; raising the floor killed the entire `legacyTabs` branch (~150 lines), the
  Translation `@available(macOS 15, iOS 18)` guard, and the `ProgressiveBlur`
  `@available(iOS 17, tvOS 17, macOS 14)` guard. Only one gate remained legitimate:
  `if #available(tvOS 27.0, *)` for `tabViewSidebarHeader`.
- **`.v26` requires exactly `swift-tools-version: 6.2`; `.v27` requires `6.4`** (compiler-verified
  against `PackageDescription.swiftinterface`). This is the one hard dependency — the *language
  mode* can stay Swift 5 independent of the tools-version.
- **Swift 6 language mode does not need to move at the same time**, and this report recommended
  against it. Rivulet — which calls itself "Swift 6" in its own docs — actually ships
  `SWIFT_VERSION = 5.0` + `SWIFT_APPROACHABLE_CONCURRENCY = YES` +
  `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. That combination is Apple's own sanctioned stepping
  stone: `SWIFT_APPROACHABLE_CONCURRENCY`'s Xcode spec condition is literally "effective Swift
  version is 4, 4.2, or 5" — it exists *for* pre-6 code. **This app followed the same recipe.**
- **silo-apple is not a "one target" example** — it ships three app targets (iOS/tvOS/macOS)
  generated by XcodeGen with `excludes:`, and still carries **784** `#if os` directives across 548
  files (vs. this app's 158 across ~223). The lesson taken: the fix is folder structure and a thin
  per-platform dispatcher file, not more targets. `EXCLUDED_SOURCE_FILE_NAMES[sdk=...]` gives the
  same folder-exclusion effect in a *single* target if ever needed (compiler-spec-verified, not
  exercised on this repo).
- **tvOS downloads: the API compiles, but the constraints are real.**
  `URLSessionConfiguration.background` + `sessionSendsLaunchEvents` + `isDiscretionary` all compile
  cleanly on tvOS. But `AVAssetDownloadURLSession` (HLS offline) is tvOS-unavailable
  (compiler-verified), `volumeAvailableCapacityForImportantUsageKey` is tvOS-unavailable (no way to
  ask "how much free space"), and `Documents` does not reliably survive relaunch on Apple TV — only
  `Caches` does, and the system can purge it between launches. Net: tvOS downloads are only viable
  as a cache with an explicit "the system may remove this" UI, not as durable storage. This
  matches, and predates, the app's current `Downloads are non-TV only` policy.
- **tvOS 27 turns on Dynamic Type system-wide** (WWDC26 session 221) — Apple names hard-coded font
  sizes and fixed frames as the direct cause of breakage, i.e. exactly this app's card layout at the
  time (see report 01). Also: `UIScreen.main` is deprecated on both tvOS 26 and iOS 26
  (compiler-verified warning); the app had three call sites in `BestVideoQualityFinder.swift`.

## What was available at baseline 26 (compiler-verified highlights)

Cross-platform already at 26: `\.horizontalSizeClass`, `\.dynamicTypeSize`, `\.isFocused`,
`ViewThatFits`, `containerRelativeFrame`, `.refreshable`, `.presentationDetents`, `.searchable` all
compile identically on tvOS/iOS/macOS — several `#if os` guards around them were already dead code
before this report. `.controlSize` finally has a visible effect on custom tvOS views at 26.
`.buttonSizing(.flexible)` is new at 26 (replaces `Spacer()`/`maxWidth: .infinity` inside buttons).

Permanently platform-specific (compiler-verified unavailable on tvOS): `TabViewCustomization`,
`.commands`/`CommandGroup` (macOS/iPadOS-26 menu bar), `Settings` scene, `Window` scene,
`MenuBarExtra`, `openWindow`/`windowResizability`, `Translation`/`TranslationSession` (the
`Translation.framework` binary now ships in the tvOS SDK, but the session type itself stays
unavailable — a real trap for anyone trying to simplify an existing `canImport(Translation)` guard),
`AVAssetDownloadURLSession`, `volumeAvailableCapacityForImportantUsageKey`,
`UIApplication.statusBarOrientation`.

## What this became in the app

- Packages raised to `platforms: [.macOS(.v26), .iOS(.v26), .tvOS(.v26)]`,
  `swift-tools-version: 6.2`, with `swiftLanguageModes: [.v5]` explicitly set — the report's Phase-2
  recommendation (approachable concurrency without a full Swift 6 language-mode jump), not Phase-4
  (`SWIFT_VERSION = 6.0`), which stayed a deferred, separate decision.
- `legacyTabs` and the surrounding `@available(iOS 18, tvOS 18, macOS 15)` branch in
  `TabsNavigationView` are gone.
- `Downloads are non-TV only` is now a stated policy (`AGENTS.md`), consistent with this report's
  storage findings above rather than contradicting them.
- `@Observable` migration and the `SWIFT_APPROACHABLE_CONCURRENCY` phase were scoped here as
  *separate, later* PRs (in that order: target raise → approachable concurrency → `@Observable`
  leaf-to-root → Swift 6 language mode last, "if ever needed") — check current feature docs for
  whether/how far that migration actually proceeded before treating this ordering as still current.

## What was borrowed

**silo-apple**: a thin per-platform dispatcher view at the top of a screen (one `#if`, not ten
scattered through the body) as the primary pattern to copy — not their three-target split, which
this report's own `#if` count (784 vs. 158) argues against. Also: a size-class-driven column count
helper (superseded here by `containerRelativeFrame(count:)`, per report 01), a form-width cap on
iPad, and a `deviceStorage()` stub returning zero on tvOS where real capacity APIs are unavailable —
directly reusable for the tvOS-downloads storage-accounting gap above.

**Rivulet**: the "Swift 6 without Swift 6 language mode" recipe (`SWIFT_APPROACHABLE_CONCURRENCY` +
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` + `SWIFT_VERSION = 5.0`) that this app's package settings
now mirror; using `actor` for non-UI services (cache managers, download indexes) rather than
`@MainActor class` for everything.

## tvOS pitfalls and unresolved questions from this report

Real findings worth re-checking if downloads-on-tvOS is ever revisited: Apple TV `Documents`
survivability and `Caches` eviction behavior were **never device-verified** in this pass — sourced
from documentation and developer forums only. TLS minimum for `URLSession` rose to 1.2 at the 26
SDK; whether kino.pub's API host supports 1.2 was flagged as a pre-migration check, not confirmed
here. `.commands`/menu-bar behavior on iPadOS 26 without an explicit `UIApplicationSceneManifest`
was untested. Scene-based life cycle became mandatory for apps built with the 27 SDK — worth
re-checking `INFOPLIST_KEY_UIApplicationSceneManifest_Generation` coverage if/when the app moves to
27.
